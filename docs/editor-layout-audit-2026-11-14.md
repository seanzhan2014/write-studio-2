# 编辑模式页面检测 · 2026-11-14

本次围绕“阅读正文 → 进入编辑 → 查找/输入/保存或放弃 → 返回阅读”检查电脑与手机页面，并回归正文候选、删除确认、改写来源、全文编辑、导航和页面溢出。

## 问题与处理

| 编号 | 问题 | 处理 |
| --- | --- | --- |
| E01 | 电脑端阅读区没有编辑框的边框，工具栏高度也不同；切换产生横向偏移、换行差异及约 6px 的纵向移动。 | 对齐边框、换行规则和工具栏最小高度。 |
| E02 | 手机编辑画布左右边距从 16px 变成 12px，还取消宽度上限；正文可用宽度改变，原来的句子会重新换行。 | 阅读和编辑使用相同的文字宽度、边距和底部留白。 |
| E03 | 按滚动百分比恢复位置；编辑前后可见高度和换行一变，同一百分比对应不同的文字。混合长短段落的复现中移动约 1100px，包含手机工具栏收起的位移。 | 按实际字符及其在内容区内的位置恢复，取消百分比映射。 |
| E04 | 没有文本选区时，以全文字符数乘滚动百分比猜测光标位置；段落长短不一时可能落到别的段落。 | 双击/双击触摸使用实际点击位置，键盘或菜单进入使用可见文字位置。 |
| E05 | 展开审校报告后由整页滚动，切换编辑后变成正文内部滚动；单独保存正文 scrollTop 会丢失阅读位置。 | 捕获外层裁切后的可见字符，切换滚动容器时继续显示该段落。 |
| E06 | 在文末切换时，可见高度变化会改变最大滚动距离。 | 单独保留“已读到末尾”的状态，切换及退出后继续停留在文末。 |
| E07 | 查找按钮只修改选区，电脑端远处的查找结果可能仍在屏幕外。 | 选择上一个/下一个结果时同步滚动到选区。 |
| E08 | 手机查找栏绝对定位覆盖正文；单行控件还会挤出视口，复选框被输入框宽度规则撑开。 | 查找栏参与正常布局；手机分行显示全部按钮，复选框保留自身尺寸。 |
| E09 | 不区分大小写的“全部替换”将 `$&`、`$$` 等当作正则替换指令，而区分大小写时按原文替换。 | 两种模式均按用户输入的原文替换。 |
| E10 | 14/15px 正文字号直接用于手机编辑框，有 iPhone 聚焦自动缩放风险。 | 手机阅读与编辑统一最小 16px，保留更大的设置字号；电脑仍遵循 14–24px 设置。实际 iPhone 缩放未用实机验证。 |

同时取消专注模式编辑框的固定最小视口高度，避免编辑区受可见高度限制时被强制撑大。

## 既有检查失败

`implementation-contract.test.mjs` 在修改前提交 `e4a577dadae81fad20376a6655dc421a926d990d` 与修复后均为 32 项通过、以下 6 项失败。它们是对源码结构的断言失败，不能直接等同于已复现的页面或数据故障。本次没有修改这些业务逻辑。

1. `schema-extensible inserts name their columns explicitly`
2. `cloud sync uses a database-version baseline and manual overwrite escape hatches`
3. `full outline and full content editors use one continuous auto-growing document`
4. `AI Generate keeps the prompt primary and automatically sets completed bodies as current`
5. `mobile Generate edits use an explicit draft save and insecure HTTP clipboard fallback`
6. `dedicated naming is centralized and all-name generation is one durable background task and one model call`

原有正文测试强制要求按滚动百分比恢复位置，该实现断言已经移除，改由真实浏览器中的文字坐标检查覆盖。

## 验证边界

手机仍采用现有的紧凑编辑工具栏，进入编辑后正文区域会向上扩展。本次保证同一段落、换行与光标的对应关系；不会把键盘弹出前后的绝对屏幕坐标视为必须相同。

WebKit 检查使用手机视口模拟，键盘检查使用可见视口事件；没有连接 iPhone 或 Android 实机，未验证真实输入法候选栏、中文组合输入和系统缩放。本次也不代表已穷尽全应用所有业务流程。

人工检查中，本地 Vite 预览的既有 Service Worker 曾导致刷新后样式丢失；独立生产构建未复现。生产验证使用正式构建，测试数据均位于独立本地测试数据库。
