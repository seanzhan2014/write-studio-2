# Writer Studio 界面审查与统一改进方案

日期：2026-09-08。范围：现有工作台的页面、任务面板、表单和浮层。本文先记录审查证据，再作为本轮界面修复的验收基线。

## 结论

当前最主要的问题是信息和操作没有按照使用频率分层：重复的标题、常驻说明、低频参数和大块输入框共同占用首屏，主要操作随表单下沉。字号偏小与容器偏大同时存在，造成“内容很多、有效操作很少”的感受。

最终统一为：**主要任务直接可用，各模块保持可见，并按真实内容量分配宽度和高度；共享控件尺寸、页面结构和浮层操作栏。** 短参数并排，长文本独占宽行，不能再依靠折叠隐藏来解决密度问题。

## 本轮实施状态

- AI Generate 已取消重复标题，压缩大纲、生成方式和常用参数；审校、片段、同时命名和推理设置保持可见，并分别使用窄列、开关列和宽内容列。
- 生成按钮和模型选择集中到持续可见的底部操作区；无任务时不再显示空的“进行中”面板。
- AI Review 已改为章节/模型、本次要求、规则正文、推理设置和固定操作栏；规则使用主宽列，推理使用较窄侧列，手机自动改为单列。
- 全站 UI/标签/元数据字号提升为 14/13/12px，常规控件基准提升为 38px，手机交互继续保持至少 44px。
- 768–1023px 已解除 900px 最小宽度，并为文章侧栏、设置双导航和设置行提供专门布局，避免隐藏式裁切。
- 人物、关系、Review 规则和 Provider 卡片只保留主要动作，归档、删除、检测等进入“更多”；人物关系改用结构化编辑表单。
- 全章节命名的新增名称与推理参数保持可见：新增名称使用紧凑行，模型、指令和推理按 1:2:1 编排；结构生成也按长指令、短模型和推理区域分配空间。
- 已移除限制页面缩放的 `maximumScale: 1`，并把业务界面的 `PoC`、`reasoning_effort` 等内部术语替换为产品语言。

## 验证结果

- 生产构建通过；ESLint 检查通过。
- 全量逻辑测试 222/222 通过。
- 桌面与手机响应式回归共 138 项：88 项通过，50 项按目标平台正常跳过，0 项失败。
- 实际复查 1280×720、820×900、390×844：Generate 主操作保持可见，820px 工作台无页面级横向裁切，AI Review 操作栏固定可达。

## 已测量的问题

### 1. 首屏空间被低频信息占用

| 场景 | 实测 | 影响 |
| --- | --- | --- |
| 1280×720，实际大纲内容 | AI Generate 可滚动内容高约 1673px，可视内容区 623px；大纲输入框约 257px | 用户需要越过大量既有内容和参数才能开始生成。 |
| 1280×720，单行测试大纲 | 大纲输入框仍约 126px；开始生成按钮顶部约 y=1341 | 内容很短时，默认最小高度和固定模块仍导致很长的页面。 |
| 390×844，单行测试大纲 | 大纲框约 151px；三种生成方式整体约 211px；开始生成顶部约 y=1688 | 单纯把桌面元素改为纵向排列显著增加手机操作距离。 |
| 390×844，AI Review 默认五条规则 | 开始审校和取消按钮约 y=1049 | 规则正文优先于本次任务输入和操作。 |

这些值来自当时的内容、默认状态和视口，不是所有数据下的固定高度。

### 2. 控件大小与内容复杂度不匹配

- 审校循环次数是一个短数字，容器却允许宽至 420px；推理模式下拉框也占据独立宽行。
- 全章节编辑采用约 0.72 : 1.28 的两列网格，新增推理控件进入第二列后，简单下拉框比补充命名要求更宽。
- 生成方式每项同时显示标题和说明；手机每项约 66px，三项加间距占约 211px。
- 大纲、补充指令都有独立“已保存 + 禁用保存按钮”区域，和全局保存状态重复占位。

### 3. 阅读与操作尺寸缺少统一标准

- 全局 UI/标签/元数据字号分别为 13/12/11px，个别眉题更小。
- 原生控件、Mantine、局部 CSS 各自定义尺寸；新增模块有独立 13px 说明和 420px 宽度，未沿用同一套字段规格。
- 手机不少触控区域已达到 44px，这是现有优点；应减少冗余容器和说明，而非压缩触控面积。

### 4. 平板断点存在真实裁切

在 820×900 下，工作台和主内容的右边界实测为 900px；右侧约 80px 被裁切。根因是工作台 `min-width: 900px`，而解除最小宽度的手机规则只在 `max-width: 767px` 生效。页面根节点隐藏溢出，因此看不到横向滚动提示。

这应先于一般视觉精简处理。

## 全站统一规则

### 信息层级

1. 主层：当前对象、必要输入、最常用参数、一个明确主操作。
2. 次层：上下文摘要、人物/片段选择、审校规则、推理强度、候选版本，保持可见并依据内容长度使用窄列、宽列或独占行。
3. 详情层：实现机制、来源/版本、完整日志、模型参数含义，通过“详情”或可点击帮助查看。

界面密度通过网格比例、控件高度和文案精简解决，不把完整模块折叠起来。重要结果提示仍应紧邻相关操作，例如“完成后更新当前正文，旧版本保留”，以及同步覆盖方向和 API Key 范围。

### 建议尺寸基准

以下为产品设计目标，不作为外部标准的强制数值。

| 项目 | 桌面 | 手机 |
| --- | --- | --- |
| 常用标签、按钮、导航 | 14px | 14–16px |
| 表单输入、常规阅读内容 | 16px；编辑器沿用用户字号 | 输入至少 16px；正文沿用用户字号 |
| 次要元数据/帮助 | 12–13px | 12–13px |
| 常规控件高度 | 36px；需要时统一使用 40px 档 | 至少 44px；主按钮可 48px |
| 图标视觉尺寸 | 16–20px | 18–20px，触控区域至少 44×44px |
| 短数字字段宽度 | 约 88–120px | 按可用宽度排列，避免单个数字占满一行 |
| 常规选择器宽度 | 约 200–280px；长模型名允许更宽 | 可用宽度，长值可截断并查看完整值 |
| 间距 | 4/8/12/16/24/32px 级别 | 同一序列，常见外边距 12–16px |

页面布局按主内容容器宽度响应。侧栏展开后放不下两列就改单列；768–1023px 不得继续强制 900px，侧栏应可折叠或抽屉化。

### 文案规则

- 每个任务只保留一个主标题；去掉已在导航或标题表达过的眉题、角标和说明。
- 每个字段默认仅显示标签、当前值和必要单位；常驻帮助最多一条短句。
- 标签已能解释的内容删除，例如“留空或 0 表示不限字数”可由“不限”状态或占位表达。
- 生成方式使用“新写 / 改写 / 续写”分段选择；只在需要时显示当前模式的一句关键差异。
- “根据当前及前序大纲中的姓名、别名推测”放人物选择面板帮助；主表单显示“首次出场 · 3 人”。
- “选择后保存为默认模型”用明确的默认状态/交互表达，避免每个模型选择器重复长句。
- 普通生成任务使用“默认 / 自定义”等产品语言。`reasoning_effort` 的精确参数语义保留在模型设置或帮助内；区分“不指定参数”与“无推理”，不能合并成一个含糊的“关闭”。
- 风险提示、错误、不可用原因和与用户输入有关的例外保留，按状态出现。
- 帮助入口必须支持点击和键盘访问，手机不能依赖悬停。

### 页面与浮层结构

- 工作页面：简短标题栏 + 工作内容 + 主操作区。表单主操作在页面滚动时保持可见，预留底部空间避免覆盖最后一个字段。
- 列表页面：工具栏 + 列表。每项保留主要动作，其余进入“更多”；新增表单在用户点击后出现。
- 设置页面：复用标签与控件对齐的设置行，长字段另起一行；减少多层导航对内容宽度的占用。
- 浮层：标题固定、单一内容滚动区、操作栏固定。短确认按内容取高；长表单手机全屏；版本比较可宽抽屉/全屏。
- 保存交互需要一致：支持自动保存的字段用简短状态；必须显式保存的字段在修改后显示保存动作和离开保护。不要只删除按钮而改变现有保存语义。
- 手机键盘出现后，输入区、当前光标和主操作不能互相遮挡；短横屏以可编辑和可关闭为优先。

## AI Generate 的具体重排

桌面主内容足够宽时，可使用“输入区 + 参数区”两列；窄屏自然排列成一列。

1. 顶部沿用当前大纲标题和工作模式导航，不再显示第二套“正文生成 / 大纲名 / 正文”。
2. 输入区先展示大纲摘要，已有大纲默认 3–5 行；点击展开完整编辑。无大纲时直接显示可输入状态。补充指令放在其后，预设入口与指令同行。
3. 常用参数紧凑排列：生成方式、目标字数、对白密度。改写保留度只在改写模式出现。
4. “参考内容”一行汇总前序大纲、人物与优秀片段；展开后调整首次出场、参考范围等内容。
5. “生成后审校”显示关闭或已启用摘要；启用后再显示修正次数、本次审校要求和规则详情。推理强度、同时命名等进入高级选项，摘要反映非默认设置。
6. 固定操作区集中放模型、上下文总量、开始生成；保留一条“更新当前正文，旧版本保留”的简短结果说明。
7. 无进行中任务时收起整块“进行中”空面板；有任务/失败时在操作附近显示状态，详细历史通过任务抽屉查看。

手机生成方式仍用紧凑分段控件或选择器，不能重新变成三张说明卡；主按钮保持至少 44px 触控高度。

AI Review 复用同一个任务表单：章节和模型 → 本次要求 → “5 条生效规则”的可展开摘要 → 固定开始/取消。规则管理本身保留完整编辑能力。

## 实施组织与顺序

1. 先修平板宽度裁切，确保所有主操作实际可见。
2. 在共享层补齐字段宽度、控件高度、间距、说明文案和固定操作栏约定。已有 Mantine 和 `app/ui/overlays.tsx` 可复用，不需要再引入组件库。
3. 以 AI Generate 和 AI Review 实施一套可验收样板，并提取共享的任务表单、字段行、可展开高级设置和操作栏。
4. 将同一规则应用于结构生成、命名、模型配置、规则管理、人物、数据管理与版本/任务面板。
5. 最后清理重复 CSS 和绕开统一浮层的实现。删除原规则前确认所有消费者已经迁移，避免简单叠加更多覆盖规则。

主要实施位置：`app/WriterStudioApp.tsx`、`app/globals.css`、`app/ui/overlays.tsx`、`app/ui/reasoning-settings.tsx`、`app/ui/review-rules.tsx`、`app/data-transfer.tsx`。

## 验收标准

- 1280×720、390×844 的默认生成状态：无需滚动即可识别生成对象、修改常用参数并看到开始按钮；长输入可在自身区域或页面中滚动，主操作不失联。
- 覆盖 320×568、390×480、667×375、768/820/900px 宽度，以及桌面 1280/1440px。真实软键盘还需真机确认。
- 检查控件自身边界与可见区域，不能只检查 `document.scrollWidth`：隐藏溢出可能掩盖裁切。
- 常规表单、菜单和弹窗遵循同一字号/尺寸档；允许清晰列出的特殊编辑器例外。
- 每个任务一个主操作，每个保存范围一个状态；默认不出现重复标题、持续禁用且无意义的保存占位。
- AI Review 的规则正文不会默认挤走本次要求和操作；删除、覆盖等相关后果提示仍可见。
- 长标题、长模型名、无数据、多任务、错误、深色模式和 200% 文本放大下仍可操作。布局元数据中的 `maximumScale: 1` 应纳入复核，避免限制用户放大。
- 复用现有响应式测试并增加“主操作首屏可见”和“平板无裁切”的针对性验收；当前已有测试偏重按钮最小尺寸与滚动可达，不能单独证明信息层级合理。
